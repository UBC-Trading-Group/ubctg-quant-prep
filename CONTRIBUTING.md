# Editing the guide

Edit the relevant HTML fragment in `src/guide/`. Keep the guide selective: explain who a resource serves, where to start and when another reference becomes useful.

Use paragraphs rather than resource bullet lists. Preserve technical detail and identify the assumptions behind examples. Do not claim firsthand teaching, reading or testing experience. Attribute quotations and distinguish recommendations from employer statements. Link to original authors, publishers and official firm guidance where possible.

Preserve existing section IDs so saved links continue to work. Keep the white background, black text and `#892736` accents. Provide descriptive alternative text for images and explanations alongside figures.

Before publishing, run `npm run build`, preview the production output at its repository base path, check narrow and wide layouts, test section links and the expandable answer, and check any external links you changed. Do not publish the internal resource inventory or revive the retired question/game directories.
